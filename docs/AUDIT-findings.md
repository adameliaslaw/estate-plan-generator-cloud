**Method.** 16 parallel read-only auditor subagents scoped across the whole codebase (11 backend clusters + 5 frontend), **weighted toward the ~71 files / +3,721 lines that changed since the Round 1-4 baseline `5879857`** — modules the earlier rounds never saw (real Dropbox Sign e-sign + HMAC webhook, transcripts pipeline, `auth-guards`, `firm-secrets`, `client-context-aggregator`, `cost-estimator`, `weekly-digest`), the lightly-covered wills pipeline, and a regression check on the ~40 shipped fixes. **Result: 137 raw findings → 136 verifier-CONFIRMED → 133 after de-dup. 1 🔴 · 29 🟠 · 64 🟡 · 39 ⚪. 123 are genuinely new (not in rounds 1-4).** The lead hand-verified 11 of the top findings against source (marked ✔); three verifier severities were corrected on that pass — the sole 🔴 (R5-001 LawPay 100×) was **downgraded to a likely false positive** after checking AffiniPay's docs (see below), and `firestore.rules:282` "self-escalation" downgraded to ⚪. **Net after corrections + B19 shipped: 0 open criticals; 3 live-broken functions fixed (#87).**

### 🚩 Headline — the regression that matters most

**The AR secret migration (#59) missed three call sites, and all three are LIVE-BROKEN for the production firm (elias-counsel).** #59 moved per-firm API keys off the client-readable firm doc into a Functions-only `firms/{firmId}/secrets/apiKeys` subcollection, and updated ~19 load sites to merge them via `loadFirmSecrets()`. Three were not updated — they still read keys off the raw firm doc, which no longer has them:

- **R5-006 `ai-compliance-check.ts:191` (checkDocumentCompliance)** — no `loadFirmSecrets()` merge **and** the `onCall` block declares no `secrets:` binding, while the call hardcodes `model:'gpt-5.4'` (→ OpenAI). So `firmData.openAiApiKey` is gone and `process.env.OPENAI_API_KEY` is unbound → **no API key at all → every compliance check throws for every firm.** (hand-verified)
- **R5-005 `review-document.ts:344` (reviewDocument)** — no merge; the live firm's model is `claude-opus-4-8`, whose Anthropic key has no env fallback → **document review throws for the live firm.** Compounded by R5-007/008: `sanitizeForPrompt(content)` uses its default 5,000-char cap, so the `.slice(0,30000)` is dead code and the compliance/review verdict is computed from only the first ~1/6 of a will/trust. (hand-verified)
- **R5-016 `weekly-digest.ts:124` (sendWeeklyDigest)** — passes the raw firm doc to `getSendGridKey()`, which reads the now-migrated `sendGridApiKey` → throws → **every firm silently skipped ("SendGrid not configured"); the weekly digest never sends.** (hand-verified)

**Fix is one line each:** merge `...(await loadFirmSecrets(firmId))` into `firmData`. **✅ SHIPPED — batch B19 (#87, merged `c6bbea6`, 2026-07-06):** all three functions now merge `loadFirmSecrets()` after sanitizing (secrets kept raw for routing); a full sweep confirmed these were the only three missed sites. Also raised the two AI-review functions' `sanitizeForPrompt` cap to 30k (was silently 5k → verdict computed from ~1/6 of the doc; R5-007/008 folded in). tsc clean, 640/640 tests pass; live callable behavior verifiable only post-deploy.

### Other hand-verified new findings

- **R5-001 ~~🔴~~ → ⚪ LIKELY FALSE POSITIVE (resolved 2026-07-06 by research).** The verifier claimed AffiniPay's hosted-page `amount` param is **dollars** → 100× overcharge. Checked the authoritative AffiniPay/8am docs (`developers.8am.com/merchant/hosted-payment-pages.html`): the parameter table lists `amount=1000` with **no stated unit**, and the whole AffiniPay/8am platform (incl. the charge API this app already uses) denominates amounts in **cents** — so `amount=1000` = $10.00, and `createPaymentRequest` passing cents (L272/L308) is **consistent and correct**. No 100× bug. Residual: the doc doesn't state the unit *in words*, so a one-time **$1.00 live test link** to confirm it renders $1.00 (not $100) closes it for certain. **This was the sole 🔴 — with it downgraded, Round 5 has zero open criticals.**
- **R5-021 `lawpay-integration.ts:311`** — `readOnlyFields:'amount,description'` omits `reference`, so the BN reconciliation key (`firmId::clientId::paymentDocId`) is an **editable** field on the page; a payer who edits/clears it breaks webhook reconciliation → incomplete BN fix.
- **R5 `register-client.ts:176`** — `registerClientFromLink` claims any **unlinked** client record for the caller's (possibly anonymous) session on a bare email match, no `email_verified` / identity proof → reads/writes another person's estate profile. Same root as BL/EJ, third call site; #70 added auth+rate-limit but not identity proof.
- **R5 `template-learning.ts:97`** — `arrayUnion({ …, timestamp: serverTimestamp() })` — Firestore rejects a `serverTimestamp()` sentinel inside an array → `recordCorrection` throws on every call → the templatization-learning feature records nothing.
- **R5 `CurrencyField.tsx:69`** — clearing a currency field makes `parseCurrency('')` return `undefined`; `firebase.ts` does **not** set `ignoreUndefinedProperties`, so the next questionnaire autosave throws `invalid-argument` and **all autosaves break for the session** (intake is the data source for every document). Distinct root cause from CH.
- **R5 `DocumentVault.tsx:807`** — the Drive-sync `Tooltip` renders outside the `TooltipProvider` (L207-373); may crash the vault tab (Radix-version-dependent — browser-check).

## Systemic themes (candidates for one encompassing fix)

- **T1 — Error handling swallows/mislabels failures.** Findings B, E. Save/bookkeeping failures get reported as success or flattened to a generic `internal` code. Candidate for a single error-propagation convention across the pipeline entry points + orchestrator.
- **T2 — Duplicated logic that can drift.** Findings G, H. Spouse-swap rules and doc-type metadata duplicated; redundant defaults/ternaries.
- **T3 — Heuristic regex rewriting of attorney-reviewed legal prose.** Finding L (+J, O). `template-engine.ts` runs ~15 regex/string passes that mutate rendered legal text (normalizeTestatorTitle, normalizeSpouseTitles, repairAiArtifacts, cleanEmptyListSlots, insertOxfordAnd, uppercaseKnownNames, typographyCleanup…) plus an AI "smooth the prose" pass. Each is individually defensible but collectively they're a fragile, hard-to-test corruption surface operating on legal documents. Worth a consolidated test harness (golden-file snapshots) rather than per-pass patches.
- **T4 — Hardcoded / literal-fallback AI models bypass per-firm provider routing.** Findings M, N, AJ. Two paths hardcode a model; all 9 generators use `model: documentDraftingModel || 'gpt-5.4'` whose literal fallback forces OpenAI when a firm picks another provider but leaves `documentDraftingModel` unset. Resolve once against the provider-dispatch contract (fall back to `undefined`, let `callAI` pick the provider default).
- **T5 — Silent data/output loss in the AI generators (no truncation signal).** Findings AF (🔴 input truncated to 5000 chars), AH (output-truncation flag is dead code), AI (no empty-content guard). The generators can silently lose both **input** (canonical data block capped) and **output** (response cut at maxTokens, saved as a clean draft). One shared `runStandardGenerator()` helper (finding AK) would fix AF/AH/AI/AJ in a single place.
- **T6 — Missing role checks on ~15 callables → within-firm client escalation. ✅ FIXED (#56 + #57, deployed green).** Root: `link-client.ts:112` mints `role:'client'`+`firmId`+`clientId`, so a client *passes* firm-scoping and reaches staff-only ops that only check `firmId`. Fix: shared `functions/src/auth-guards.ts` (`assertStaff`/`assertFirmStaff`) applied to all staff-only callables (v2 via `assertStaff`, v1 via equivalent inline role check) — 18 in #56 (connectGoogleDrive, exchangeGoogleAuthCode, chatAi, listAiConversations, getDocumentVersions/getDocumentVersionContent, summarizeTranscription, checkDocumentCompliance, groundedReviewDocument, generateEstateDocument, saveMessageAsNote, enhanceTemplate, calendar push/pull, triggerFirmCalendarSync, sendForSignature, lookupPropertyData, estimateGenerationCost) + the 6 email senders & testSendGridConnection in #57 (**BJ**). `sendQuestionnaireCompleteNotification` intentionally left un-gated (client-triggered on questionnaire submit). **Residual (reclassified to T9):** server-resolve email recipients + HTML-escape interpolated fields.
- **T7 — Broken firm-scope predicate (cross-tenant read).** `if (callerFirmId && callerFirmId !== firmId && role !== 'admin')` — a no-`firmId`-claim caller skips the throw, and any firm `admin` reads cross-firm. In `getTemplateContent`, `searchKnowledgeResources`, `listTemplates`. Fix: unconditional `callerFirmId === firmId` via a shared `assertFirmAccess` helper.
- **T8 — Raw storage paths in admin-SDK downloads (cross-tenant file read). ✅ FIXED (#58, deployed).** The admin SDK bypasses Storage rules, so functions must validate path prefixes themselves; `bulkProcessKnowledgeFiles`, `processQuestionnaireScan`, `transcribeAudio` used caller-supplied `storagePath`/`imagePaths` raw. `processTemplateFile` was the correct template (validates prefix). Fix applied to all three: require `path.startsWith('firms/{firmId}/')` + reject `..`. Guard inlined per call site (not via `auth-guards.ts`) because two are v1 callables where a v2 `HttpsError` would be re-wrapped as `internal`.
- **T9 — Missing Zod / unbounded inputs into AI + email.** Cost/DoS and content-injection surface: chatAi, enhanceTemplate, generateFlexDocument, saveMessageAsNote, createFirmUser/updateUserCapabilities, plus raw user strings interpolated into firm-branded email HTML. Fix: Zod schemas with length caps at every callable boundary; server-resolve email recipients; sanitize interpolated fields.
- **T10 — Revoked OAuth (`invalid_grant`) never persists a disconnected state.** Calendar (`calendar-sync.ts:304-316`) and Drive (`google-drive-sync.ts:114-138`) throw on revoke; the scheduled/triggered job swallows it and retries forever — the firm is never told to re-auth. This is the code-level root of the recurring Calendar `invalid_grant` in memory [[project_google_oauth_refresh_token_expiry]]: even after the consent-screen fix, nothing surfaces re-auth need. Fix: on `invalid_grant`, write `connected:false`/`authError` and show it in the UI.
- **T11 — No transient-retry/backoff on any external call.** ai-client (S), calendar, drive, SendGrid, Whisper, AssemblyAI poll, CourtListener, ATTOM all treat the first 429/5xx as terminal (some abort mid-job/mid-pagination). One shared backoff helper hardens all of them.
- **T12 — Stub integrations report success.** esign returns `{success:true}` + writes "sent for signature" with no send (BU); Levitate's API-key path posts to a self-described mock endpoint (CD); email `scheduledReminders` is commented out so the advertised 24-hour reminder never fires (CF). Each tells staff/clients a legal/CRM action happened that didn't.
